# BudjetKeeper — PWA для учёта финансов в стиле CoinKeeper

## Контекст
Новое приложение с нуля (каталог `/home/ig/Work/BudjetKeeper` пуст). Это личный учёт для двух человек с одним общим бюджетом. Каждый вносит операции со своего устройства (iPhone, iPad, Android), и изменения сразу видны у второго. Механика взята из классического CoinKeeper 1/2:
**источники дохода → счета → категории расходов**. Операция создаётся перетаскиванием «монеты» одной иконки на другую, новые элементы добавляются плитками «+». Статистики и отчётов в MVP нет.

Принятые решения: **Supabase** (Postgres, Realtime, Auth), **одна валюта (₽)**, **у каждого свой логин** в общем «бюджете», **только онлайн** (без сети показываются последние данные, но вносить операции нельзя).

## Стек
- Vite + React + TypeScript, `vite-plugin-pwa` (manifest и service worker для оболочки приложения)
- `@supabase/supabase-js`: auth, запросы, канал Realtime `postgres_changes`
- `zustand`: клиентское хранилище
- `lucide-react`: набор иконок для монет
- Перетаскивание сделано своими силами на Pointer Events: «призрак» монеты под пальцем и поиск цели через `document.elementFromPoint`. Такой вариант надёжнее библиотек при перетаскивании между разными зонами на iOS Safari.
- Vitest: юнит-тесты логики
- Локальная разработка через Supabase CLI (`supabase start` в Docker, Docker установлен). Миграции лежат в `supabase/migrations`.
- Хостинг фронтенда: Cloudflare Pages или Vercel (бесплатно, HTTPS обязателен для PWA). Переменные окружения: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.

## Модель данных (`supabase/migrations/0001_init.sql`)
- `households(id, name, invite_code, created_at)`
- `household_members(household_id, user_id, display_name)`, PK по паре полей
- `entities(id, household_id, kind ∈ {income, account, expense}, name, icon, color, plan_kopecks null, position, archived, created_at)`: источники, счета и категории в одной таблице
- `transactions(id, household_id, from_id, to_id, amount_kopecks bigint > 0, comment, occurred_at date, created_by, created_at)`
- Допустимые пары проверяются триггером: `income→account` (доход), `account→expense` (расход), `account→account` (перевод)
- Суммы хранятся в копейках (`bigint`), без float
- Представление/RPC `entity_totals(month_start)`:
  - счёт: баланс за всё время (приход − расход)
  - доход и категория: сумма за выбранный месяц
- RLS на всех таблицах через `is_member(household_id)` (security definer)
- RPC `create_household(name, display_name)` и `join_household(invite_code, display_name)`
- Таблицы `entities` и `transactions` добавлены в публикацию `supabase_realtime`

## Синхронизация
- После входа клиент загружает `entities` и `entity_totals(текущий месяц)`
- Подписка на канал `household:{id}`, `postgres_changes` по `entities` и `transactions` с фильтром `household_id=eq.{id}`. На любое событие: точечно обновить entity, а итоги перезапросить (данных мало, это дёшево и всегда корректно).
- Своя операция показывается оптимистично; при ошибке откатывается с тостом
- При возврате вкладки (`visibilitychange`) и после переподключения выполняется полная перезагрузка, чтобы не пропустить события, пока iOS держал PWA в фоне

## Экран (по второму макету)
Сверху вниз, с учётом safe-area:
1. **Шторка доходов** (зелёная): по умолчанию свёрнута, открывается язычком со стрелкой. Монеты источников показывают «получено / план».
2. **Ряд счетов** (кирпичный): горизонтальный скролл, если их больше 4. Под монетой баланс.
3. **Сетка категорий** (тёмная): 4 колонки, горизонтальные страницы с точками. Монета показывает «потрачено» и план мелким шрифтом, уровень заполнения круга равен потрачено/план (жёлтый, при перерасходе красный).
4. **Нижняя панель**: «Настройки» и итог месяца (доходы и расходы, без графиков).
- В конце каждой секции стоит плитка **«+»**, она открывает шторку создания (имя, иконка из набора, цвет, план для дохода/категории).

### Взаимодействия
- **Перетаскивание**: на монете дохода или счёта жест начинается после сдвига больше ~6px или долгого нажатия ~200мс. Скролл/свайп страниц отличается по направлению и задержке. Над монетой появляется «призрак», допустимые цели подсвечиваются, недопустимые затемняются. Отпускание над целью открывает **шторку суммы**.
- **Шторка суммы**: «откуда → куда», крупная цифровая клавиатура с `+ − × ÷` (как в CoinKeeper), дата (по умолчанию сегодня), комментарий, «Готово».
- **Тап по монете**: шторка элемента с редактированием (имя, иконка, план, архивировать) и списком последних операций. Операцию можно изменить или удалить, это нужно для исправления ошибок.
- CSS для монет: `touch-action: none`, `user-select: none`, `-webkit-touch-callout: none`; вибрация `navigator.vibrate` при захвате (на Android).

## Визуальный стиль
Стилистика Things 3 (с 2026-10-25): белый фон (тёмный — графитовый), непрозрачные шторки, синие заголовки секций
над тонкой линией вместо карточек, плоские монеты (счета и доходы — диск цвета, категории — светлая подложка
с цветным значком), палитра значков Things. Токены цветов в `:root`, светлая/тёмная/авто тема.
Ряды сетки категорий подбираются по измеренной высоте монеты, свободная высота делится между рядами.

## Порядок реализации
1. Создать каркас Vite + PWA + Supabase client, поднять `supabase start`, написать миграцию с RLS и RPC
2. Auth (email и пароль) и онбординг (создать бюджет или присоединиться по коду)
3. Store, загрузка данных, Board с тремя секциями, плитки «+», создание и редактирование элементов
4. Перетаскивание, шторка суммы с калькулятором, запись операции
5. Подписка Realtime и перезагрузка при возврате вкладки
6. Шторка элемента со списком операций (изменение и удаление)
7. Доводка под PWA: manifest, иконки, safe-area, meta-теги для iOS, запрет pull-to-refresh и масштабирования
8. Деплой фронтенда и облачный проект Supabase

## Проверка
- **Юнит-тесты (Vitest)**: `money.ts` (копейки и форматирование, калькулятор выражений), `rules.ts` (допустимые пары)
- **БД**: на локальном Supabase SQL-проверки, что пользователь вне бюджета не видит и не может вставить данные (RLS), а триггер отклоняет `expense→account` и сумму ≤ 0
- **Синхронизация**: `npm run dev`, два окна Chrome в эмуляции мобильного устройства под двумя пользователями одного бюджета. Расход в одном окне сразу виден во втором. Проверить через Chrome DevTools MCP.
- **Перетаскивание**: проверка в эмуляции тача (drag источник → счёт, счёт → категория, счёт → счёт, отказ на недопустимой цели)
- **Реальные устройства**: превью-деплой (или туннель с HTTPS), «На экран Домой» на iPhone и iPad, установка на Android. Проверить перетаскивание пальцем, safe-area и синхронизацию между телефонами.
